A. FUNDAMENTAL & BUSINESS QUESTIONS
--------------------------------------------------------------------------------

Q1: Why not just use Stripe or credit cards?
Answer: Economics. Stripe charges $0.30 + 2.9% per transaction. If our API call costs $0.001, the payment processor's fee is 300x larger than our revenue. Even with transaction batching, credit card rails introduce chargeback risks, global currency conversion friction, and delayed settlement. USDC on Arc settles instantly for a micro-fraction of a cent.

Q2: Why build on the Arc blockchain instead of other L2s/L1s?
Answer: Arc provides the ultra-low latency and hyper-optimized block space necessary for true programmatic micropayments. Gas costs on Arc drop to ~$0.000001, meaning charging $0.001 yields a 99.9% profit margin on the network layer. Furthermore, native integration with Circle stablecoin tooling ensures robust enterprise-grade liquidity.

Q3: How do developers make money charging only $0.001?
Answer: High frequency and scale. AI inference and specialized small-task APIs (summarization, localized weather, translation queries) are called millions of times a day by automated pipelines and agents. A pay-as-you-go model drastically expands the top-of-funnel user base by removing subscription paywalls, driving massive aggregate volume.

Q4: Do you plan to launch your own native token?
Answer: No. Launching a volatile custom token introduces unnecessary friction, cognitive load, and accounting headaches for enterprise consumers. By utilizing USDC as our core native currency, we guarantee stable, predictable pricing where an API call costs exactly the same today as it will next year.

--------------------------------------------------------------------------------
B. TECHNICAL & ARCHITECTURAL QUESTIONS
--------------------------------------------------------------------------------

Q5: Explain exactly how the x402 protocol integration works under the hood.
Answer: It is a 4-step flow:
1. Challenge: The client requests a protected endpoint (e.g., `/api/weather`). The server intercepts this and responds with an HTTP status code `402 Payment Required`, returning a JSON payload specifying the price ($0.001 USDC) and the receiver's address (`payTo`).
2. Payment: The client catches the 402 response. Using the Circle Developer Wallets SDK (or injected Web3 provider), it triggers an on-chain transfer of the requested USDC amount to the receiver's address on the Arc Testnet.
3. Verification: Once the transaction confirms, we obtain a unique transaction hash (`txHash`).
4. Data Access: The client automatically queries an internal data-mirror endpoint, logging the verified transaction hash, and receives the raw service data alongside cryptographic proof of payment.

Q6: How does the wallet generation work without requiring browser extensions?
Answer: We integrate the `@circle-fin/developer-controlled-wallets` SDK. When a user clicks 'Create Wallet', our backend securely calls Circle's API using our entity secret and API keys. Circle generates an untraceable, secure EOA wallet set tied programmatically to the user's session ID. The user doesn't manage private keys; Circle acts as the secure multi-party computation (MPC) custodian.

Q7: On Arc Testnet, how is gas paid for these developer-controlled wallets?
Answer: On the Arc Testnet configuration, native token transfers handle gas natively. Because gas fees are astronomically low, users simply need a minor top-up of testnet USDC from the Circle Faucet to cover hundreds of consecutive API calls smoothly.

Q8: What happens if a transaction fails or gets stuck during execution?
Answer: Our backend polling architecture checks transaction states programmatically. When a transfer is initiated via `circleSDK.createTransaction`, we capture the Circle Transaction ID. We poll `circleSDK.getTransaction` every 2 seconds for up to 30 seconds. If the status returns 'FAILED', 'DENIED', or times out, the client safely rolls back the API call and displays a clear error without consuming user funds.

Q9: How do you prevent users from bypassing the gateway and hitting the underlying API directly?
Answer: In production, backend endpoints are strictly segmented. The public gateway routes verify transaction completion logs or require pre-signed authorization tokens before relaying requests to the protected internal microservices (represented by our `DATA_MIRROR` routing logic).

Q10: Explain the purpose of the Circle Gateway Bridge component shown in the dashboard.
Answer: The Gateway Bridge is currently a frontend concept demonstrating our roadmap for cross-chain interoperability. In the future, we plan to fully integrate Circle's Cross-Chain Transfer Protocol (CCTP) so developers can seamlessly bridge their existing USDC liquidity from Ethereum, Base, or Polygon directly onto the Arc network to fund high-frequency API consumption.
